# Connect Four

Connect Four has two separate user interfaces: an Expo/React Native Android app at the repository root and a React/Vite browser app in `web/`. Both use the same game rules, WebRTC connection session, signaling format, and move messages from `src/`.

## Project structure

```text
.
|-- App.tsx
|-- app.json
|-- package.json
|-- package-lock.json
|-- jest.config.js
|-- tsconfig.json
|-- android/
|-- src/
|   |-- assets/
|   |-- game/
|   |-- networking/
|   |-- screens/
|   `-- __tests__/
`-- web/
    |-- index.html
    |-- package.json
    |-- package-lock.json
    |-- tsconfig.json
    |-- vite.config.ts
    `-- src/
```

### Root and Android app

- `App.tsx` routes between the main menu, connection screen, and game screen, and transfers the connected session into gameplay.
- `app.json` configures the Expo app and its native camera, image picker, WebRTC, sharing, and asset plugins.
- `package.json` and `package-lock.json` define and lock the Android app's Expo, React Native, networking, and development dependencies.
- `tsconfig.json` sets the mobile app's TypeScript options. `jest.config.js` configures Jest with the Expo preset and locates tests under `src/__tests__/`.
- `android/` contains the generated native Android Gradle project, wrapper, and APK build outputs. Run `npm.cmd run android` to generate or build and launch the custom development app.

### Shared code in `src/`

- `src/game/types.ts` defines the board, player, position, and game-state types.
- `src/game/board.ts` creates an empty board and defines its row and column counts.
- `src/game/checkWinner.ts` finds the winning line after a move.
- `src/game/game.ts` creates game state and applies legal moves, wins, and draws.
- `src/game/index.ts` exports the public game rules and types used by both apps.
- `src/networking/PeerSession.ts` manages the WebRTC peer connection, Offer/Answer exchange, DataChannel, connection state, and cleanup. It uses browser WebRTC on web and `react-native-webrtc` on Android.
- `src/networking/signalingPayload.ts` validates and compresses Offer/Answer descriptions for transfer in a QR code.
- `src/networking/iceGathering.ts` waits for ICE candidate gathering before creating a signaling payload.
- `src/networking/gameMessages.ts` encodes and validates moves and forfeit messages sent between peers.
- `src/networking/index.ts` re-exports the networking API.
- `src/screens/MainMenuScreen.tsx` shows local play, host, and join choices in the Android app.
- `src/screens/ConnectionScreen.tsx` handles Android camera scanning, Offer/Answer QR display and sharing, and gallery selection with a square crop. Gallery scans run the same `qr-scanner` decoder as web inside a local WebView.
- `src/assets/qr-scanner-bridge.html` bundles the browser scanner and bridge used to decode gallery images in the Android WebView. `QR_SCANNER_LICENSE.txt` contains its license.
- `src/screens/GameScreen.tsx` renders the Android board and synchronizes online moves and forfeits.
- `src/__tests__/game/` tests the game rules; `src/__tests__/networking/` tests signaling, ICE gathering, peer sessions, and messages; `src/__tests__/screens/` tests the app and screen flows.

### Browser app in `web/`

- `web/package.json` and `web/package-lock.json` define and lock the browser app's separate dependencies and commands.
- `web/index.html` is the Vite HTML entry point. `web/src/main.tsx` mounts the React app and global styles.
- `web/src/webApp.tsx` implements the browser menu, game board, WebRTC connection, camera/gallery QR scanning, QR sharing, and copy/paste signaling fallback.
- `web/src/style.css` contains the browser app's layout and responsive styling.
- `web/vite.config.ts` configures Vite and keeps the Android-only WebRTC fallback out of browser dependency scanning.
- `web/tsconfig.json` configures TypeScript for the web app and shared modules. `web/src/vite-env.d.ts` supplies Vite's client types.
- `web/dist/` is generated by a production build; it is not source code.

## How to run

### Android mobile app

Use Node.js 22.13 or newer. For native builds, install Android Studio with the Android SDK and a compatible JDK. From the repository root, install dependencies and launch the custom development build on a connected phone or emulator:

```powershell
npm.cmd install
npm.cmd run android
```

The app uses native WebRTC and needs a custom development build; Expo Go is not supported. For JavaScript-only work after the development build is installed, start Metro with:

```powershell
npm.cmd start -- --dev-client --lan
```

Keep the phone and computer on the same network, then open the project from the installed Connect Four development client.

To create a standalone release APK for local installation:

```powershell
cd android
.\gradlew.bat assembleRelease
```

The APK is written to `android/app/build/outputs/apk/release/app-release.apk`. The current Gradle release configuration uses the debug signing key for local testing; it is not signed for Play Store distribution.

### Web app

The web app has its own dependencies. From the repository root:

```powershell
cd web
npm.cmd install
npm.cmd run dev
```

Open the local URL printed by Vite. Camera access requires `localhost` or HTTPS and browser permission. To play online, open the app on two browsers/devices: choose **Host a game** on one and **Join a game** on the other. The host shows an Offer QR; the joiner scans it and shows an Answer QR for the host to scan. The browser version also supports gallery image selection and cropping, QR sharing or download, and copy/paste signaling as a fallback.

The Android and web clients use public STUN for direct WebRTC discovery and have no TURN relay, so some restrictive networks may block peer connections.

## Checks

Run the Android app's tests and typecheck from the repository root:

```powershell
npm.cmd test
npm.cmd run typecheck
```

Build and typecheck the web app from `web/`:

```powershell
npm.cmd run build
```
